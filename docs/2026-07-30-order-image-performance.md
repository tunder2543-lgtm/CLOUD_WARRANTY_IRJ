# แก้อาการหน่วง/ค้างตอนเปิดออเดอร์ที่มีรูปเยอะ

วันที่: 2026-07-30

## ปัญหา
โมดัลแก้ไขออเดอร์แสดง **รูปต้นฉบับเต็มความละเอียด** เป็นภาพย่อ และโหลดทุกรูปพร้อมกัน
- ใน bucket `warranty-images`: 265 รูป · เฉลี่ย 2.5 MB/รูป · สูงสุด 18 MB · รวม 657 MB
- ออเดอร์ 54 รูป = ดาวน์โหลด+decode ~135 MB พร้อมกัน → โมดัลค้าง
- จัดเรียงรูป (◀▶⭐) เรียก `renderModalImgs()` สร้างกริดใหม่ทั้งหมดทุกครั้ง → decode ซ้ำ
- Supabase image transform (ย่อฝั่งเซิร์ฟเวอร์) **ใช้ไม่ได้** บนแพลนนี้ (endpoint คืน 403)

## การแก้ไข
### 1) แสดงตัวอย่างแค่ 6 รูป + ปุ่ม "ดูรูปทั้งหมด" (`js/orders.js`)
- `renderModalImgs()` แสดง `IMG_PREVIEW_LIMIT = 6` รูปแรก + ปุ่ม `ดูรูปทั้งหมด (N)` → กดแล้วขยายครบ
- เพิ่มรูปใหม่ → ขยายอัตโนมัติ (`mImgShowAll=true`) เพื่อเห็นรูปที่เพิ่ง add
- ทุก `<img>` ใช้ `loading="lazy"` + `decoding="async"` → โหลดเฉพาะที่เลื่อนมาเห็น

### 2) บีบอัดรูปตอนอัปโหลด (`js/helpers.js` + `js/orders.js`)
- `compressImageBlob()/compressImageFile()`: ย่อด้านยาวสุด **1600px**, JPEG คุณภาพ **0.85**,
  PNG คงเป็น PNG (ย่อขนาด), คงชื่อ/นามสกุลเดิม (ไม่ต้องแก้ DB), ข้ามถ้าไม่เล็กลง
- `saveOrder()` เรียก `compressImageFile()` ก่อน `Store.uploadImage()`
- ผลจริง: PNG 18 MB → 1.9 MB (ลด ~90%)

### 3) ปุ่มย่อรูปเก่า (migration) — `js/settings.js` + หน้า "⚙️ ตั้งค่า"
- ปุ่ม "🗜️ บีบอัดรูปเก่าให้เล็กลง" → ยืนยัน → ไล่ทุกไฟล์ใน `warranty-images`:
  โหลด → `compressImageBlob()` → เขียนทับ (`upsert`) ที่ path เดิม พร้อม progress
- **เขียนทับไฟล์เดิมถาวร** (กู้ความละเอียดเดิมไม่ได้) — เป็นปุ่มให้ผู้ใช้กดรันเอง ทำครั้งเดียว

## ขอบเขต
- โฟกัส `warranty-images` (รูปออเดอร์) · ไม่แตะคลัง Live (elec) รอบนี้
- ไม่ใช่ real-time; migration รันจากเบราว์เซอร์ (ไม่มี image transform ฝั่งเซิร์ฟเวอร์)
- bump `?v=` → 30 (แสดง 6 รูป) → 31 (บีบอัด + ปุ่ม migration)

## หมายเหตุ
หลังบีบอัดรูปเก่า URL เดิมไม่เปลี่ยน → เบราว์เซอร์ที่ cache รูปใหญ่ไว้อาจเห็นของเก่าจนกว่า cache จะหมดอายุ
(ไฟล์ที่เก็บเล็กลงจริงแล้ว ผู้เข้าใหม่/หลัง cache หมดจะได้ไฟล์เล็ก)
